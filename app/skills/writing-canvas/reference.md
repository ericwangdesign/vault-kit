# Writing canvas: the reference

Generated by `node canvas/check.mjs --docs` from the checker's catalog, its arcs and `canvas/shapes.mjs`. Never edit this file: change those and regenerate. The checker reads the same examples, so a field that isn't listed here does nothing and gets flagged.

## Arcs

| Arc | For | Slots, in order |
|---|---|---|
| `decision` | A choice, made or still to make. Why, and what it costs. | beforeAfter, figure, variants, compare, live → flow, sequence, tree, steps, figure, beforeAfter → compare, variants, matrix, live → decision (last) |
| `shipped` | Something changed. What, where, and what is still open. | beforeAfter, tabs, live → tree, flow, sequence, figure, steps, table → timeline, stats, checklist |
| `explainer` | How something works, for someone new to it. | figure, tree, flow, sequence, steps, tabs, live → flow, sequence, steps, figure, compare, variants, chart, table, treemap, live |
| `plan` | What happens next, and when. | gantt, timeline, calendar, steps, checklist → decision, compare, stats, checklist |
| `review` | A look back at a stretch of my own work. | stats, chart, treemap → timeline, gantt, calendar, heatmap → variants, beforeAfter, figure, tabs |
| `reference` | A catalog page: one of each shape, shown on real data. Only for the system's own docs. | no order |

Slots are the minimum, in order. Extra shapes may sit between them.

Stay prose when the answer is one or two sentences, or an opinion with no structure. One or two numbers are a sentence, not a chart.

## Every block

Fields marked md take `**bold**`, `*italic*`, `[link](url)` and `` `name` ``, nothing else. Every shape takes `"title"`: the sentence that says what it shows. Any shape takes `"caption"` for what it can't say itself (a source, a date that matters).

### Running text

#### `text`

```json
{ "type": "text", "md": "Paragraph.\n\nAnother paragraph." }
```
- Needs: `md`.
- One or two sentences between shapes. A blank line starts a new paragraph.

#### `heading`

```json
{ "type": "heading", "text": "A menu hid the work" }
```
- Needs: `text`.
- Becomes an h2 and a rail entry. Says the point, under 40 characters.

#### `list`

```json
{ "type": "list", "items": ["md", "md"] }
```
- Needs: `items`.
- Three or more short items. Most lists are a shape.

#### `quote`

```json
{ "type": "quote", "md": "The one line worth remembering.", "cite": "optional" }
```
- Needs: `md`.
- One per page at most.

#### `aside`

```json
{ "type": "aside", "title": "optional", "md": "A side note." }
```
- Needs: `md`.
- A side note the main text doesn't need. On a page that isn't a decision, the honest cost and the open question can live here.

#### `collapsible`: What's underneath?

Depth a careful reader wants and a skimmer does not: the brief, the method, the raw notes. One line on show.

```json
{ "type": "collapsible", "title": "md: what's inside, as a label", "note": "md: one line under it", "open": false,
  "blocks": [ ... ] }
```
- Needs: `title`, `blocks`.
- Depth a skimmer can skip. Never hide the point in one. Two in a row stack as one group.

### Change

#### `beforeAfter`: What changed?

Any visible change. Real screenshots or clips, same size, same moment. A side can hold blocks instead.

```json
{ "type": "beforeAfter", "title": "md: what changed",
  "w": 1700, "h": 1600,
  "before": { "label": "Before", "src": "/media/x-before.jpg", "srcLight": "/media/x-before-light.jpg", "alt": "...",
              "pins": [ { "x": 78.8, "y": 8.3, "text": "md: what is wrong here, in one line" } ] },
  "after":  { "label": "After",  "src": "/media/x-after.jpg", "alt": "...",
              "pins": [ { "x": 3.8, "y": 65.8, "text": "md: what changed and why" } ] },
  "caption": "md", "start": "before" }
```
- Needs: `before`, `after`.
- `x`, `y` are percent of the image. 2 to 4 pins per side, each one line a non-designer understands.
- If the UI has a light mode, add `srcLight` to each side, same crop, same moment, so pins land on the same spot in both.
- A side may be `{ "label": "...", "blocks": [ ... ] }` instead of a picture (a tree each side, paragraphs vs a decision). Then there's no Slide mode, and only one side shows at a time: say the change in the title so the skim path still works.
- Two options you haven't picked between are a `compare`, not a before/after.

### Choice

#### `compare`: Why this and not that?

2+ options judged on the same 3+ things.

```json
{ "type": "compare", "title": "md", "options": ["Option A", "Option B"], "picked": 0,
  "rows": [ { "label": "md", "values": ["md", "md"] } ], "caption": "md", "pickLabel": "Picked" }
```
- Needs: `options`, `rows`.
- 3 to 6 rows. Values are short phrases, not sentences.
- Leave `picked` out when nothing is picked yet: a choice still to make starts here.

#### `variants`: What did we try?

2 to 6 options you can see: explorations, rounds, or every state of one thing.

```json
{ "type": "variants", "title": "md: what won, and over what",
  "cols": 2, "w": 980, "h": 76, "fit": "cover",
  "items": [ { "label": "md", "note": "md: one line on why it lost or won", "src": "/media/x-1.jpg", "srcLight": "...", "alt": "...", "picked": true },
             { "label": "md", "md": "a text-only variant, when there's no picture", "mark": "gone" } ],
  "pickLabel": "Picked" }
```
- Needs: `items`.
- 2 to 6 items. `w` and `h` set one crop for all (`"fit": "contain"` shows the whole picture). `cols` is 1 to 4; a very wide picture (a tab strip) wants `cols: 1`.
- At most one `picked`. With none it's a set of states. `mark: "gone"` fades a rejected one.
- `pickLabel` renames the badge when nothing was chosen: "Shipped", "The main one".
- An item with no `src` is a small card: `label`, then `md`, then `note`.

#### `matrix`: Where does each option sit?

3+ options judged on two things at once.

```json
{ "type": "matrix", "title": "md", "x": { "label": "Who decides the look", "low": "The model", "high": "A renderer" },
  "y": { "label": "What it can draw", "low": "A few shapes", "high": "Anything" },
  "items": [ { "label": "The canvas", "x": 92, "y": 16, "key": true } ], "quadrants": ["optional", "four", "corner", "names"],
  "caption": "Placed by judgement, not measured." }
```
- Needs: `x`, `y`, `items`.
- `x` and `y` are 0 to 100, low to high. A judgement says it is one, in the caption.

#### `decision`: So what did we pick?

Every page about a choice ends with one. Not made yet: leave out `chose` and say the question in `open`.

```json
{ "type": "decision",
  "chose": "md: the call, in one or two sentences.",
  "why":  ["md", "md"],
  "cost": ["md"],
  "open": "md: what's still undecided, and who it's waiting on",
  "sign": ["Decided Oct 5 in design review", "Built Oct 9"],
  "label": "Decision", "whyLabel": "Why", "costLabel": "What it costs" }
```
- Always include `cost`. A decision with no cost isn't honest.
- Not made yet: leave out `chose` and put the question in `open`. It heads the card under "Not decided yet", and `why` and `cost` can hold what pulls each way.

#### `tabs`: How does it look in each case?

2 to 5 views of the same thing: sizes, rounds, arcs. Two with a slide is beforeAfter.

```json
{ "type": "tabs", "title": "md: what the views show", "start": 0,
  "tabs": [ { "label": "Phone", "blocks": [ ... ] }, { "label": "Desktop", "blocks": [ ... ] } ] }
```
- Needs: `tabs`.
- 2 to 5 panes of blocks. Two views with a slide is a `beforeAfter`.

### Structure and how it works

#### `tree`: Where does everything live?

Any structure 2+ levels deep. `mark` shows what moved.

```json
{ "type": "tree", "title": "md", "root": { "label": "md", "note": "md", "mark": "new|gone|moved", "key": true, "children": [ ... ] }, "caption": "md" }
```
- `roots: [...]` for several top-level nodes. Labels are names, 1 to 3 words; explanation goes in `note`.
- `key` lights the path that matters (a name's route, the file in question) with no badge. `mark` is only for change: new, gone, moved.
- On its own a tree is a canvas you can pan and zoom, so a big one is fine. A phone shrinks it to fit: keep notes short.
- Also takes: `roots`.

#### `flow`: How does it behave?

States or screens with a branch, a retry or a failure. A straight line is steps.

```json
{ "type": "flow", "title": "md: what the flow guarantees",
  "nodes": [ { "id": "press", "label": "md", "note": "md" },
             { "id": "stopped", "label": "Stopped", "kind": "end", "key": true },
             { "id": "fail", "label": "It won't stop", "kind": "fail", "row": 2 } ],
  "edges": [ { "from": "press", "to": "stopping", "key": true, "label": "md, optional" },
             { "from": "fail", "to": "stopping", "label": "Try again" } ] }
```
- Needs: `nodes`, `edges`.
- Columns come from the arrows: each node sits one column right of what leads to it. List the main path first; it's row one. `row` puts a branch on its own row.
- An arrow back to an earlier node or to itself is drawn as a loop in its own lane. Several loops may come back to the same node.
- A node nothing points to (a timer, a second way in) sits one column before what it leads to. `key` makes the main path blue (and wins over `kind`). `kind`: `end` (filled), `fail` (dashed).
- Up to 8 nodes, labels 1 to 4 words. The column fits about three across; more stack top to bottom with branches side by side, and a phone turns three branches into one list, every arrow that skips a row in a lane on the right.
- One party asking several others in turn, answers coming back (a resolver, a checkout), is a `sequence`, not a flow: a flow says each node hands off to the next.

#### `figure`: What is it made of?

With `pins`: one screen and what its parts are for. Without: a picture the text needs.

```json
{ "type": "figure", "title": "md: what the screen is, in one line", "src": "/media/x.jpg", "srcLight": "/media/x-light.jpg",
  "w": 1440, "h": 900, "alt": "...", "pins": [ { "x": 32.2, "y": 27.2, "text": "md: this part, and what it's for" } ], "caption": "md" }
```
- Needs: `src`.
- Without `pins`: a picture the text needs; a tall one stops at 560px high and sits centred on a card the column's width.
- With `pins` it's an anatomy: 3 to 5 numbered notes on what the parts are for, listed under the picture. Put a pin beside its target, never on it.
- `src` ending .mp4 or .webm plays as a silent loop; `poster` is its still. Less-motion readers get the still and a play button.
- Also takes: `poster`.

#### `sequence`: Who asks whom, in what order?

One party asking 2+ others in turn, with answers coming back: a lookup, a checkout, an API call. 2 to 5 parties.

```json
{ "type": "sequence", "title": "md: what the exchange shows",
  "parties": [ { "id": "you", "label": "Your browser" }, { "id": "res", "label": "Resolver", "note": "from your wifi", "key": true }, { "id": "root", "label": "Root" } ],
  "steps": [ { "from": "you", "to": "res", "label": "Where is the vault?" },
             { "from": "res", "to": "res", "label": "Not in its memory", "note": "md, optional" },
             { "from": "res", "to": "root", "label": "Where is it?" },
             { "from": "root", "to": "res", "label": "Ask com", "reply": true, "key": true } ] }
```
- Needs: `parties`, `steps`.
- Parties are the columns, left to right in the order they first come in; 2 to 5, one or two words each, the rest in `note`. Steps run top to bottom, each an arrow with its label above.
- `reply: true` dashes an answer coming back. A step from a party to itself (a cache, a check) is a small loop with its label beside it. `key` makes one step, or the party doing the asking, blue.
- Step labels under 5 words: a label gets only the width between its two parties, and a phone fits five parties across.
- Each box hands off and is done: a `flow`. One party keeps asking and gets answers back: a sequence.

#### `steps`: What happens, in order?

A process someone goes through, 3 to 6 steps, no branches.

```json
{ "type": "steps", "title": "md", "items": [ { "title": "md", "text": "md", "key": true } ], "caption": "md" }
```
- Needs: `items`.
- A process someone goes through, 3 to 6 steps, no branches. `key` marks the step that matters.

#### `code`: What does the code say?

A few lines that carry the point: a config, a spec, a diff. Up to 30 lines; `mark` the ones that matter.

```json
{ "type": "code", "title": "md: what the lines show", "lang": "JSON", "mark": [3, 4], "numbers": true,
  "code": "line one\nline two" }
```
- Needs: `code`.
- The one place the canvas uses mono (Geist Mono). Up to 30 lines. `mark` lights the lines that matter, 1-based.
- With `"diff": true`, lines start with `+ `, `- ` or two spaces. Copy copies the result, without the removed lines.
- Line numbers start at 1; for an excerpt of a real file, `"numbers": false` and say where it's from in the title.
- Also takes: `diff`, `file`.

#### `table`: What are the details of each?

Rows of things with the same 3+ fields. Options judged on criteria is compare.

```json
{ "type": "table", "title": "md: what the rows add up to",
  "columns": ["Header", "Max age", { "label": "Use it for", "align": "left" }],
  "rows": [ ["`Cache-Control`", 3600, "Everything"], { "cells": ["...", "...", "..."], "key": true } ], "unit": "" }
```
- Needs: `columns`, `rows`.
- Rows of records with the same fields, up to 15. Number columns align right on their own. `key` on one row makes it blue.
- A rule table ("if this, use that") is a table with the condition first. Options judged on criteria is `compare`.
- Keep `code` chips in cells short; a phone wraps long ones.
- Also takes: `prefix`, `decimals`.

### Time

#### `timeline`: How did we get here?

3+ dated or ordered events.

```json
{ "type": "timeline", "title": "md", "items": [ { "when": "Oct 5", "title": "md", "text": "md", "key": true } ], "caption": "md" }
```
- Needs: `items`.
- `key` marks the one or two moments that matter. `when` is 6 characters or fewer ("Oct 5", "Mon 12", "Next").

#### `gantt`: How long, and what overlaps?

3+ things with start and end dates.

```json
{ "type": "gantt", "title": "md", "today": "2026-10-12",
  "items": [ { "group": "optional heading", "label": "Seattle", "start": "2026-10-08", "end": "2026-10-13", "note": "md", "key": true },
            { "label": "Fly home", "start": "2026-10-13" } ],
  "legend": { "key": "Now", "bar": "Other dates", "dot": "One day" } }
```
- Needs: `items`.
- An item with no `end` is one day (a dot). Dates are YYYY-MM-DD, ends inclusive.
- Notes are 2 or 3 words: a phone's label column is narrow. A time of day goes in the note ("9:35pm").
- Dates stay inside the chart and step around the Today line on their own.
- `legend` renames the marks, or `false` drops it.

#### `calendar`: What's on which day?

Events you look up by date, within one to three months.

```json
{ "type": "calendar", "title": "md", "month": "2026-10", "today": "2026-10-12",
  "events": [ { "label": "LA with friends", "start": "2026-10-23", "end": "2026-10-26", "key": true } ] }
```
- Needs: `events`.
- `months: ["2026-10", "2026-11"]` for more than one; with neither it shows every month the events touch.
- A phone cell fits about four letters. Repeating events are listed one by one.
- Also takes: `months`.

#### `heatmap`: When did it happen, and how much?

An amount per day over 3+ weeks, to show the rhythm and the gaps.

```json
{ "type": "heatmap", "title": "md", "days": { "2026-10-10": 25, "2026-10-12": 49 }, "from": "2026-09-01", "to": "2026-10-12",
  "today": "2026-10-12", "unit": "saves", "steps": [1, 5, 15, 30] }
```
- Needs: `days`.
- 3+ weeks. One square a day, weeks left to right, Monday on top. One week by day is a bar chart with `"order": "given"`.
- Also takes: `less`, `more`.

#### `checklist`: Where does it stand?

A plan's items, each done, doing, open or blocked.

```json
{ "type": "checklist", "title": "md: where it stands",
  "items": [ { "label": "md", "state": "done|doing|open|blocked", "when": "Oct 12", "note": "md" } ] }
```
- Needs: `items`.
- The count ("3 of 7 done") sits by the title on its own; don't repeat it in the title.
- Waiting on someone else is `blocked`, with who in the note. One `doing` at a time reads best.

### Amounts

#### `stats`: How much?

2 to 4 numbers that carry the point, each with what it is compared to.

```json
{ "type": "stats", "items": [ { "value": 13, "label": "about colour", "vs": "almost half", "key": true, "trend": [4, 6, 9, 13] } ], "unit": "" }
```
- Needs: `items`.
- 2 or 4 numbers (3 leaves one alone on a phone). `trend` draws a sparkline, 5+ points.
- Numbers are raw; `unit`, `prefix`, `decimals` format them for the block. A value can be a string when it needs its own format ("3.0", "9:35").
- Also takes: `prefix`, `decimals`.

#### `treemap`: What is it made of, by size?

5 to 15 parts of one whole, or parts with parts. 2 to 4 parts is a share chart.

```json
{ "type": "treemap", "title": "md", "data": [ { "label": "Ideas", "value": 43, "children": [ { "label": "Toys", "value": 17, "key": true } ] },
  { "label": "Projects", "value": 23 } ] }
```
- Needs: `data`.
- 5 to 15 parts sized by area. A part with `children` splits again inside. Mark the one part that matters, not its parent.

#### `chart`: Which is biggest? What share? Up or down?

bar: 3 to 12 amounts. share: 2 to 4 parts of a whole. ring: one value out of a whole. funnel: 3 to 8 steps people drop out of, in order. line: 5+ points in time.

```json
{ "type": "chart", "kind": "bar", "title": "md: the finding", "data": [ { "label": "Colour", "value": 13, "key": true } ],
  "reference": { "label": "Target", "value": 10 }, "order": "given", "unit": "%" }
{ "type": "chart", "kind": "share", "title": "md", "data": [ { "label": "Tasks page", "value": 18, "key": true } ] }
{ "type": "chart", "kind": "funnel", "title": "md: where people leave", "data": [ { "label": "Started", "value": 100 }, { "label": "About you", "value": 74, "key": true }, { "label": "In the app", "value": 41 } ] }
{ "type": "chart", "kind": "ring", "title": "md", "value": 3, "of": 7, "label": "milestones done", "note": "md", "show": "3 of 7" }
{ "type": "chart", "kind": "line", "title": "md",
  "series": [ { "name": "notes", "key": true, "points": [ ["2026-09-01", 32], ["2026-10-12", 97] ] } ],
  "marks": [ { "at": "2026-09-14", "label": "What changed here" } ], "zero": false }
```
- Needs: `kind`.
- The title is the finding. One thing is blue (`key`, or name it in `highlight`); the rest stay grey. Bars start at zero and sort longest first unless `"order": "given"`.
- Real data only, sourced in a caption or `foot`. An explainer's typical curve says "illustrative, not measured" in its caption.
- Ring: one value out of `of` (100 if left out); the middle shows the percent unless `show`. One ring per chart. No pie, donut, gauge, radar or dual axes.
- Funnel: steps in the order people go through them, never sorted. Each bar is who's left; the faint piece after it is what that step lost, with the drop in percent. `key` on the step where people leave makes its loss the blue thing.
- Line: x can be dates or text labels (`marks.at` then names a label). Up to 4 series, 2 marks; a `null` is a gap. Only the ends carry numbers: a peak that matters goes in a mark's label.
- Also takes: `highlight`, `points`, `name`, `prefix`, `decimals`.

### Something to use

#### `live`: What happens when I try it?

The point lands by doing: drag, tune, pick, filter, play. A page's own <template>, or a page of its own in a frame.

```json
{ "type": "live", "title": "md: what trying it shows", "template": "picker", "caption": "md" }
```
- The piece is the page's own HTML: `<template id="picker">markup and <script></template>` anywhere in the body, named by `template`. Its scripts run in order once the page is drawn; `document.currentScript.closest('.cv-live')` is its own block, so query inside that, never the whole document.
- Write plain elements: `button`, `input`, `select`, `label`, `output` already wear the canvas's look, `.row` lays controls in a line. Colours, sizes and space come from the vault's tokens (`var(--accent)`, `var(--text-3)`, `var(--raised)`, `var(--s3)`, `var(--t-sm)`), never a literal.
- A piece too big for a template is a page of its own: `"src": "/pages/<slug>/"`. The frame grows to the page's height (or `h` in px) and follows day and night. `alt` names it for a screen reader.
- A piece with its own ground (a canvas, a map) takes `"bare": true`: no card, no padding.
- What the reader does on it can stay: `await vault.state.get(key)` and `vault.state.set(key, value)` save to the vault, same on every device, and Claude reads them from `pages/_state/`.
- Under 390px wide it still works by touch, with no hover-only controls. It never needs a sign-in, a key or a network call outside the vault.
- Also takes: `src`, `h`, `alt`, `bare`.

### Depth and sources

#### `sources`: Where did this come from?

Claims that rest on outside work. Each source, and what it showed.

```json
{ "type": "sources", "title": "md, optional",
  "items": [ { "title": "OpenUI", "url": "https://...", "site": "optional", "note": "md: what it showed", "checked": "Oct 12" } ] }
```
- Needs: `items`.
- A letter tile stands in for each favicon, so the page loads nothing from anyone else's server. It counts as a section's shape.
